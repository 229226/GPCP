用 **RISC-V（CVA6）+ 4×4 CGRA** 做基站基带处理器原型，全部在 Verilator 仿真，目标是从时域样本一路解出完整 NR 协议过程并与 Python 黄金模型逐位对账。目前**协议能力已铺到 P4 中段、验证纪律已机制化、编译器方向已证伪并给出新路线**；项目未动 RTL，改动都在软件/工具链/文档层。

## 1. 项目是什么

- 架构：CVA6（RISC-V 控制核）+ 4×4 = 16 PE 的 CGRA（最近邻 N/E/S/W，1 拍 link 延迟）
- 目标：时域样本 → 完整 NR 协议过程，每个环节与黄金模型**逐位对账**
- 阶段划分：以「可端到端跑通的协议过程」为界，P1–P8（见 `docs/11-项目计划.md`）

## 4. 编译器议题（结论是「证伪」，不是成果）

文档链：`docs/14` 自研方案 → `docs/15` II 基线 → `docs/16` 接入尝试（共 8 节，进行中）。

- **自研编译器方案（`docs/14`）**：按用户要求**搁置**。
- **Morpher II 基线（`docs/15`）**：FIR/GEMM 都 **II=4**，RecMin II=4 来自它的「寄存器-内存回环」（我们的 acc 正是为消除它而设计）——量的是**架构差异**，不是映射质量。
- **Morpher 接入（`docs/16`）**，逐项实测结果：
  - ✅ 给 `PathFinderMapper` 打补丁导出 `schedule.csv`，容器内重编译通过，array_add 验证可用
  - ✅ 写我们自己的 ADL（16 条指令 + 8 寄存器 + acc）→ 映射成功 **II=8 / 40 s**（**更正**了此前「算子硬编码、加不了 MAC」的误判）
  - ❌ ADL 不完整：删方向寄存器 → 段错误(139)、改 SPM 尺寸 → 断言(134)，详见 §7 保真度表
  - ❌ 后端 v0 对 array_add **0/20 节点能编码**（no_op 8 / no_addr 3 / no_route 8）
  - **路线修正**：只借它的映射器（吃 DFG XML），不借 C 前端；我们自己生成纯数据流 DFG XML 喂进去，下一步是写这个 XML 生成器

## 7. 看法

- 真正值钱的是把纪律做成了**可执行的东西**：指纹缓存、门禁、台账、同步工具。门会越加越多，靠人记一定会烂。
- 两个隐患也清楚：
  1. 新门仍按「模型+硬件+checker」三件套复制，审计已量出 **6.9% 冗余**，再加下去维护成本会超过收益；
  2. Morpher 这条线目前只证明了「路走不通」，**别把它算作进展**。
- 推进建议，二选一：要么做 DFG XML 生成器把编译器闭环，要么回头做共享层把重复度压下去。
