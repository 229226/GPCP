## 2. 两个必须知道的坑

### 2.1 `LD_LIBRARY_PATH` 污染

IDE 会注入：
```
LD_LIBRARY_PATH=.../modules/ai-agent:.../modules/ai-agent/bin
```
其中的 `libstdc++.so.6` 版本过旧，导致 Verilator 内部调用的 `g++` 报
`GLIBCXX_3.4.29 not found`。

解决：
- 手工构建前 `source scripts/env.sh`（内部 `unset LD_LIBRARY_PATH`）；
- `tools/cgra.py` 已在子进程里自动清理；
- 各 Makefile 的关键命令前加了 `env -u LD_LIBRARY_PATH`。

### 2.2 Ubuntu 的 `riscv64-unknown-elf-gcc` 缺少 libc 头

直接编译会报 `#include_next <stdint.h>: No such file or directory`。
需要 picolibc 的 specs：

```bash
riscv64-unknown-elf-gcc --specs=/usr/lib/picolibc/riscv64-unknown-elf/picolibc.specs \
  -march=rv32im -mabi=ilp32 ...
```

`make sw-check` 已封装。

## 4. 资源约束提示

- 内存 7.7 GB：CVA6 全核 Verilator 构建、OpenAirInterface 全量编译会很紧张；
  优先 Ibex（M1）与 srsRAN（M2）。
- 磁盘 ~30 GB：不要把 OAI、CVA6、QEMU 源码与构建目录都长期保留；按里程碑清理。
