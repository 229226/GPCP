分支 `wip/mmse-ring`。主分支 master 不受影响，`run-mimo` 720/720 绿色。

## 已验证正确的部分

| 项 | 证据 |
|---|---|
| 新 kernel `mmse_dual`（一层算两层） | 88 拍 × 16 PE，编译期自检 0 差异 |
| 描述符表内容 | dump tile 2 的 32 条：src/dst/len 全部与期望一致（dst 0,32,2,34…，len 全 2，page 位正确） |
| y 的 I/Q 打包搬运 | 修掉"虚部源地址 4 字节对齐 → 引擎取回实部"后，172/192 位置 × 4 叶子正确 |

| 阵列运行次数 | 24 → 12 |
| 整程序周期 | 480,250 → 440,948（−8.2%） |

## 未解决：引擎静默漏做一段描述符

现象（确定性、可复现、两次运行完全相同）：

```
tile 2:  Y1R 全对  Y1I 全对   Y2R 错 k=0..10  Y2I 错 k=0..10
tile 5:  Y1R 全对  Y1I 全对   Y2R 错 k=0..8   Y2I 错 k=0..8
```

- 错的是**天线 1**（`sp[1]`）那一条描述符，天线 0 同位置全部正确；
- 读回值不是"上一趟的旧值"，而是 `0` 和 `-1`（例：k=0 源=182、spad=0；k=1 源=229、spad=-1；k=11 源=122、spad=122 正确）；
- **去掉预取重叠（把 push 移到回读之后、完全串行）结果一字不变** → 不是竞态；
- 环深 1024、描述符缓冲 416 条、实际用 384 条，无绕回；
- `RING_DONE` 在等待点确实到达期望值，所以不是"没等够"。

## 已排除的假设

1. ~~双页竞态~~：串行化后完全不变。
2. ~~描述符构造错误~~：dump 出来逐条比对，全对。
3. ~~layout 宏与写入顺序不符~~：`Y1R/Y1I/Y2R/Y2I = 0/1/32/33`，与 dst 一致。
4. ~~溢出/截断~~：把守卫阈值改成 1 立刻整段回退 CPU 并 720/720，说明 `|y| ≤ 20000` 成立。
5. ~~层 1 算术错误~~：让层 1 用层 0 系数，芯片内两组汇逐位相等（0 失配）——但该实验在"两槽位本就相同"时也会通过，不能单独作为证据。

## 结论与三条出路

搬运骨架本身成立（省 8.2%、运行次数减半），但引擎会静默丢掉"每隔一条、连续一段"的描述符，
且不报错（`probe: 0 errors`）。因此当前实现**不可合并**。

1. **换掉 y 的搬运方式**：y 仍用原来逐次 `mmse_dma`（已验证），只保留"一层算两层 + 12 次运行"的收益 → 预计仍能省 2–3 万周期，且无正确性风险。
2. **一位置一条描述符**：把两根天线的 y 在上游拼成连续 4 字，一条描述符搬完 → 描述符数 360→180，可能绕过引擎的漏做规律；代价是改 FFT 输出布局。
3. **查引擎 RTL**：需要波形级调试（`cg-dma` 的 `$display` + `RING_HEAD/DONE/DBG_STATE`），确认漏做发生在取指还是写回。

建议先做 1（低风险、当天可验证），把 2 作为"要不要真正吃下这 8%"的决策点。
