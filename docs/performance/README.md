# 性能与 PPA

## 1. 度量口径

| 指标 | 定义 | 来源 |
|---|---|---|
| 总周期 | 程序从开始到结束的时钟拍数 | 仿真台架 / 程序计数器 |
| 阵列运行次数 | `array_runs`，一次静态调度的启动 | 结果区 |
| DMA 次数 | `dma`，一次描述符或寄存器搬运 | 结果区 |
| 阵列忙拍数 | `PERF_ARRAY_BUSY`，硬件计数（全跑）；不要用软件 `busy`（只含译码） | 性能计数器 |
| 利用率 | `PERF_ARRAY_BUSY / PERF_CYCLES` | 性能计数器 |
| CGRA 覆盖率 | 阶段 / 工作量 / 有效覆盖，定义见 `tools/cgra_coverage.py` | 同左 |
| 按时率 | 1 ms 时隙内完成的传输块比例 | `proto/load.py` |

频率校正：Verilator 周期比隐含 CPU 与 CGRA 同频。实测 CVA6 fmax 约 264 MHz，
CGRA 约 1.05 GHz，**时间比 ≈ 周期比 × 4**。对外引用必须带这个校正。

## 4. PPA（Nangate45 + sky130 HD）

`cgra_top` 的逻辑网表：IMEM 与 spad 两个阵列在综合前被剔除（宽字 IMEM 需要
16 份复制宏；降成触发器会让网表爆掉），所以下表只含逻辑，存储面积单列在
下面。两套开放 PDK 走同一个 Yosys+slang → ABC → iEDA 流程，只换 liberty：

| 项 | Nangate45（45 nm，1.1 V） | sky130 HD（130 nm，1.8 V） |
|---|---|---|
| 标准单元库 | `NangateOpenCellLibrary_typical.lib` | `sky130_fd_sc_hd__tt_025C_1v80.lib` |
| 逻辑面积 | 87,306 µm²（7,504 flop，占 45.6%） | 499,869 µm²（7,504 flop，占 37.7%） |
| 单元数 | 43,753 | 47,862 |
| 关键路径（pre-layout） | 1.573 ns | 9.341 ns |
| 综合目标 / slack | 500 MHz（2 ns）/ +0.386 ns | 50 MHz（20 ns）/ +9.985 ns |
| 由关键路径推得 Fmax | ≈ 636 MHz | ≈ 107 MHz |
| 功耗（toggle 0.1，无 VCD） | 41.0 mW @ 500 MHz | 95.9 mW @ 50 MHz |
| 复现 | `make -C syn sta CLK_FREQ_MHZ=500` | `make -C syn sta PDK_NAME=sky130hd CLK_FREQ_MHZ=50` |

**口径**：两组数字是 ITER-6（spad 散列改为 GF(2) 双射后）在 HEAD 上复测的。
旧记录 78,499 µm² / 1.429 ns / 37.5 mW（ITER-4）对应的还是 `10*bank` 散列，
触发器 7,291；ITER-5 的 1R1W spad 与 ITER-6 的散列让组合逻辑增加约 11%，
触发器变为 7,504。更早的 54,148 µm² / Fmax 1.05 GHz / 23.8 mW 来自
描述符契约、窗口检查、性能计数器、IMEM 双 bank 之前的 RTL（5,072 flop），
不能与上表混用。

sky130 的 96 mW 看着高，但换算成每周期能量是 1.92 µJ/cycle，对 Nangate45 的
82 nJ/cycle 约 23×，与 `C·V²` 的 130 nm/1.8 V 对 45 nm/1.1 V 的比值（≈22×）
一致。两条关键路径都卡在**未被扇出缓冲的高扇出网**上（sky130 那条 87 扇出、
10.9 ns 转换），真实布线后会明显改善，此处只作 pre-layout 对比。

| 存储与参考 | 值 |
|---|---|
| IMEM | 0.276 mm²（2 bank × 512×512，1R1W；ITER-2 起双 bank） |
| spad | 约 0.17 mm²（8 KiB = 64 × 32×32 1R1W 宏 0.051 mm² + 16→32 交叉开关约 0.12 mm²） |
| CPU 参考 | CVA6 fmax 约 264 MHz（关键路径在 FPU FMA） |

**存储为什么不在上面的综合表里**：流程在映射前执行
`memory_collect` + `delete {t:$mem_v2}`（`syn/cgra_top_syn.tcl`），把两个阵列
整块剔除，只综合逻辑。原因是开放流程没有能装下它们的宏：

- IMEM 是 512 bit 宽字（一拍取 16 个 PE 的指令）。平铺成 8192×32 需要 16 个
  读端口，等于 16 份复制宏（16 × 32 KiB）；按宽字（64 B/行）存又没有对应宏。
- spad 现在每个物理 bank 就是一读一写（1R1W），但宏仍不在 liberty 里；
  把 8 KiB 摊成触发器会淹没逻辑面积，所以存储继续单列。

所以逻辑面积和存储面积必须分开看。把存储按宏 + 交叉开关口径估算后，
CGRA 的总面积是：

| 组成 | Nangate45（45 nm） | 占比 |
|---|---:|---:|
| 逻辑（上表） | 0.0873 mm² | 16.4% |
| IMEM（64 KiB） | 0.276 mm² | 51.8% |
| spad（8 KiB，1R1W + 交叉开关） | 0.17 mm² | 31.9% |
| **合计** | **≈ 0.53 mm²** | 100% |

**存储占 84%，IMEM 是最大单项（52%）**。spad 从 2.60 mm² 降到 0.17 mm²，
是因为每 bank 从 16R/16W 的寄存器堆变成 32×32 的 1R1W 宏 + 16→32 交叉
开关：读 mux 从 512 个 32:1 降到 16 个 64:1。sky130 一列只给逻辑
（0.500 mm²）：它还没有接 SRAM 宏 liberty，存储面积不能直接套用 45 nm 的数。

**sky130 上要把存储做进去，分别是什么情况**（现状：两个阵列在综合前都被删掉）：

| | IMEM（64 KiB） | spad（8 KiB） |
|---|---|---|
| 端口需求 | 每 bank 每拍 1 次 512 bit 读 + 1 次 32 bit 写 | 每物理 bank 每拍 **1 读 + 1 写**（1R1W） |
| 用标准单元硬综合 | 52.4 万 bit → 约 **13 mm²**（按本设计 25.1 µm²/flop）+ 读 mux | 6.6 万 bit → 约 1.6 mm² **再加 16→32 交叉开关** |
| 用 SRAM 宏 | **可行**：按 lane 切成 32 份 512×32（2 KiB）的 1W1R 宏（sky130 的 OpenRAM 宏目录有 1/2/4 KiB、单口/1W1R/双口/1RW1R 几种） | **可行**：64 个 32×32（1 KiB）1R1W 宏（同目录有 1/2/4 KiB、1W1R 等），交叉开关用标准单元 |
| 要做的事 | `imem` 拆成 16 个 lane 存储 + 拼读；加宏 liberty；用 `memory_libmap` 映射 | 加宏 liberty + `memory_libmap`；交叉开关 RTL 已在 `cgra_array.sv` 里 |

所以结论是：**两个阵列在 sky130 上都可以宏化**——IMEM 约 32 个 2 KiB
1W1R 宏（量级 1 mm²），spad 64 个 1 KiB 1R1W 宏（量级 0.1 mm²）加交叉开关。
当前流程两者都还没接宏 liberty，故上表只给逻辑；spad 的面积按 45 nm 宏
LEF 和交叉开关单元数单列（§4 上表），sky130 换库后同量级。

### 4.1 面积分布

`make -C syn area [PDK_NAME=sky130hd]` 生成（`syn/area_report.py`，明细见
`build/syn/<design>-*/area_groups.txt`）。**寄存器能精确归属**（RTL 名保留），
**组合单元不能**：slang 前端在读入时就把层次展平成单模块，ABC 再把组合单元
命名成 `_NNNN_`，所以组合逻辑只能给总量和单元类型分布。

| 功能块（寄存器） | Nangate45 | 占比 | sky130 HD | 占比 |
|---|---:|---:|---:|---:|
| PE 阵列（16 PE + 网格，寄存器） | 24,515 µm² | 28.1% | 115,311 µm² | 23.1% |
| 性能计数器 | 8,321 | 9.5% | 39,138 | 7.8% |
| 描述符环 + 拷贝引擎 + 写窗口 | 4,669 | 5.3% | 23,372 | 4.7% |
| 旋转表（32 bank × 13 bit） | 2,245 | 2.6% | 10,561 | 2.1% |
| 其他顶层寄存器（含 IMEM bank 选择） | 43 | 0.0% | 200 | 0.0% |
| **寄存器合计** | **39,797** | **45.6%** | **188,607** | **37.7%** |
| 组合逻辑（ABC 命名，无法归属） | 47,509 | 54.4% | 311,262 | 62.3% |
| **合计** | **87,306** | 100% | **499,869** | 100% |

| 单元类型（面积 Top 6） | Nangate45 | sky130 HD |
|---|---:|---:|
| 触发器 | `DFFR_X1` 44.5% | `dfrtp_1` 36.6% |
| 2:1 选择器 | `MUX2_X1` 11.2% | `o21a_1` 5.4% |
| 缓冲 | `BUF_X4` 3.3% | `buf_6` 5.2% |
| 4 输入与非 | `NAND4_X1` 2.0% | `nand4_1` 5.0% |
| 复合 AOI | `AOI21_X1` 3.9% | `o21bai_1` 2.1% |
| 4 输入与 | `AND4_X1` 3.0% | `a21o_2` 2.8% |

两条结论：

1. **性能计数器是除 PE 之外最大的单项**（9.5% / 7.8%，1,564 个 flop），比整个
   描述符环 + 拷贝引擎（5.3% / 4.7%）还大。它是纯观测设施，可以做成编译期开关
   或缩到 32 位全局 + 每 PE 采样，收益直接吃进面积。
2. **PE 阵列这一行只是寄存器**（regfile/acc/pipeline），PE 的 MAC 与 link 选择器
   落在“组合逻辑”那一桶里，所以不能读成“PE 只占 28%”。要把组合逻辑也归属，
   得改成按模块分别综合（当前 slang 前端读入即展平，只能靠名字归属寄存器）。

## 5. 已有优化

- 64 B 复合描述符：`in → array → out → repeat` 由硬件 FSM 自动滚动，中间轮次
  不写状态字，显著减少描述符数量与 CPU 干预。
- 每 bank 旋转表：把 LDPC 的逐边旋转从 CPU/DMA 搬到 spad 访问路径。
- DMA 突发：32 beat / 4 KiB 裁剪，1024 字线性拷贝 0.70 周期/字。
- 双页 ping-pong：阵列与 DMA 重叠，`run-rxchain` 4 slot 514 周期/slot。

## 6. 下一步方向

1. DMA 与阵列重叠（P1 第二项）：环内每个描述符是 `搬入 → 阵列 → 搬出` 串行，
   若允许下一个描述符的搬入在上一个阵列运行时进行（双页 ping-pong + 两深
   上下文 + 旋转表分页），decode 的 460K 可压到约 360K，FFT 两阶段同理。
2. `ofdm_modulate` + `transform`（33.9%）：每个 tile 约 9–14 次 MMIO 寄存器写，
   CPU 247K/76K 主要花在这里；把 tile 参数打包成单次提交可再省一大截。
3. decode 的 CPU 残余：环构建/校验 148K（一次性，可用 64-bit 直写 + 校验
   采样收敛）、`msg` 先验初始化 94K（可考虑下沉成 CGRA 广播/旋转 kernel）。
4. `encode`（11.5%）：纯 CPU 的 LDPC 编码，评估下沉到阵列或与 DMA 重叠。
5. spad 端口压力：按 bank 旋转表重排数据布局，降低面积与冲突。

## 7. 引用规则

- 周期比不是时间比：对外说加速比时乘 4× 频率校正，或明确写「同频周期比」。
- 利用率必须带口径：`busy / cycles`，并注明场景与运行次数。
- 任何数字都要能追溯到一条门禁命令与一次提交。
