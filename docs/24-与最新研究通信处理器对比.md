# 24 — 与最新研究通信处理器的对比（BayesBB / Ara BSoC / NUS PACE）

> 目的：`docs/22` 的对比锚点是**顺序 CPU**（CVA6，264 MHz @45nm）。本文把对比对象换成
> **最新研究中的通信处理器**——① 研究级可编程基带两条路线（专用 ASIC / 向量核），
> ② **同架构 CGRA**（NUS PACE/HyCUBE，硅片实测）——回答"GPCP 的 CGRA 在研究前沿里
> 处于什么位置"。
> 方式：文献指标 + 节点归一化（不动 RTL，1 天可复核）。
> 数据来源见各表脚注；GPCP 侧数字与 `docs/08` / `docs/22` 完全同源。

## 2. 归一化方法（粗粒度，只用于数量级）

- **面积**：`面积 × (L_target / L_ref)²`。40nm→45nm：×1.27；22nm→45nm：×4.18。
- **频率**：22FDX 对 45nm 通用库约 **1.5–2×**（FD-SOI 且先进两代）；40nm 对 45nm 约 1.1×。
- 声明：这是**线宽比例归一**，不含库风格/电压/双均差异，只能支撑数量级结论，
  不能替代同节点重综合。

## 3. 归一化到 45nm 后的面积 / 频率

| | GPCP CGRA | BayesBB | Ara (4-lane) | Ara (16-lane) |
|---|---:|---:|---:|---:|
| 原始面积 | 0.0685 mm²（逻辑） | 19 mm² @40nm | 0.68 mm² @22FDX | 2.13 mm² @22FDX |
| **归一化到 45nm** | 0.0685 mm² | **≈24 mm²** | **≈2.8 mm²** | ≈8.9 mm² |
| 归一化频率 | 1,053 MHz | — | ≈700 MHz（÷1.8 估） | ≈580 MHz |
| 归一化功耗 | 23.8–32.1 mW | — | 259 mW | — |

**面积数量级**（含存储口径 GPCP 取 0.27–2.8 mm² 区间）：

- BayesBB ≈ 24 mm²@45nm → 是 GPCP 的 **~69×**（最小口径）/ ~8.6×（现状交叉开关口径）。
- Ara 4-lane ≈ 2.8 mm²@45nm → 是 GPCP 的 **~8×**（同口径）；但 Ara 是 4 条向量 lane
  （每 lane 有 ALU/MUL/FPU + VRF），单核算力远高于 16 个 GPCP PE。

**频率**：GPCP 的 1,053 MHz 与 Ara 归一化后的 ~700 MHz 同一档——CGRA 短路径阵列
并不比向量核慢；真正拉开差距的是**每周期算力**（Ara 16-lane 峰值 32 DP-GFLOPS vs
GPCR 16 PE × 每 PE 每 2 拍一次 MAC）。

**功耗**：Ara 259 mW（跑 256×256 矩阵乘）vs GPCP 23.8–32.1 mW——GPCP 的绝对功耗低
一个量级，但这是"16 PE 小阵列"与"4 lane 向量机"的规模差，不是能效差；能效要归一到
相同吞吐才有意义（见 §5 缺口）。

## 4. "可配置"的三种粒度——三条路线的本质差异

| | 重构发生在 | 重构时间常数 | 换算法的代价 |
|---|---|---|---|
| **GPCP CGRA** | **每一拍**（微码逐拍变） | 0 拍（微码已驻留 IMEM） | 写新微码（分钟级，工具链自动生成） |
| **BayesBB** | 架构级参数（并行阶/码字参数） | 毫秒–秒级（重配置流水线拓扑） | 重综合（月级）或受限参数空间 |
| **Ara BSoC** | 指令级（RVV + 未来自定义指令） | 0（软件换函数） | 写 C/内建函数 |

- BayesBB 的"可配置"是**编译/部署期**的：全展开流水线一旦投片，支持 LDPC/polar/MIMO-BP
  的参数空间，但不支持任意新算子；
- Ara 的"可配置"是**软件期**的：任意 C 代码都能跑，但每拍吞吐受限于向量宽度；
- GPCP 的"可配置"是**数据通路级**的：16 PE 的互连/操作数/操作每拍可变——这是 CGRA
  相对两者的唯一结构优势，代价是每 PE 算力小、需要编译器把 kernel 映成微码。

## 5. 工作负载对齐的缺口（诚实标注，引用本文必须带上）

1. **规模不同**：BayesBB 面向 **128×128 cell-free mMIMO**（9.6 Gb/s 用户吞吐），
   GPCP 场景是 2×2/4×4 MIMO 的 LTE/NR/WiFi 链——**不能直接比吞吐**，只能比
   "单位面积的灵活性"与"单位算力的时延预算"。
2. **Ara BSoC 的 kernel cycle 只在论文图 1**（16×16/32×32 矩阵、VLEN 512–4096），
   正文无数值——精确对比需要联系作者或复现（Ara RTL 开源，是可做项）。
3. **GPCP 每场景的 TB 比特数**尚未从生成器推导，因此"吞吐（Gb/s）× 能效（pJ/bit）"
   的定量对比暂缺——这是本文最大的数据缺口，补齐方法：解析 `tools/*_ce.py` 各场景
   的 `cfg.derived`（NRE × qm × 符号数），除以 `compare_all.csv` 的周期数。
4. BayesBB 频率/功耗未公开检索到，需 JSSC 原文补齐。

## 6. 定位结论

- **GPCP CGRA 的位置**：面积效率极高的**轻量逐拍可重构 L1**——0.0685 mm² 逻辑
  （0.27–2.8 mm² 含存储）就覆盖 17 条 LTE/NR/WiFi 链，面积比 BayesBB 小 1–2 个数量级，
  比 Ara 向量核小 ~8×，而频率与其归一化值同档。
- **与 BayesBB 的差距 = 专用化的差距**：BayesBB 用 220× 的面积换 9.6 Gb/s 的固定
  消息传递吞吐；GPCP 不追求那个吞吐档位，追求的是"一块 0.3 mm² 的硅覆盖多标准多场景"。
- **与 Ara 的差距 = 并行宽度的差距**：Ara 的向量 lane 是成熟 64-bit FPU 流水线，
  GPCP PE 是 32-bit 定点 MAC——若对标 Ara 的浮点 LOW-PHY，GPCP 需要加宽 PE/加 lane；
  若保持定点 L1 定位，则 GPCP 的面积效率优于 Ara。
- **对 docs/22 结论的修正**：CPU（264 MHz）→ 研究级可编程基带（1 GHz 量级）的对比
  说明"通用顺序核"不是合适基线；**正确的基线是 Ara 这类向量核/轻量基带处理器**，
  这也是后续 kernel 移植实验（Ara RTL 开源）的价值所在。

## 8. 与同架构 CGRA 的对比（Onyx / PACE / HyCUBE）——最公平的参照

把对比对象换成**同架构 CGRA**后，比较的不再是路线差异，而是**设计质量**。这里选最新的
硅片 CGRA：**Onyx（Stanford，VLSI 2024 + JSSC 2025-09）**，并把 NUS PACE/HyCUBE 作为
"同为 RISC-V/ARM SoC 集成 CGRA"的次级参照。

### 8.0 研究时间线：什么才是"最新"

- **硅片级最新：Onyx（Stanford Horowitz/Raina 组）——GF 12nm，VLSI 2024 首发、
  JSSC 2025-09 全文**：CGRA SoC，首个同时支持**稀疏+密集**张量代数的可编程加速器；
  CGRA **970 MHz**、峰值 **571 INT16 GOPS**、能效 **756 GOPS/W**、CGRA 面积 **8.28 mm²**
  （整芯 23 mm²，含 GLB 4.45 mm² 与 SerDES）；
- 次新：**PACE 28nm（HotChips 2024，NUS + A*STAR IME 流片，360 GOPS/W）**及其前身
  HyCUBE 40nm（A-SSCC 2019，**753 MHz**、26.4 MOPS/mW、290 pJ/cycle，vs Zynq 28.6×）；
- **2025 年的 CGRA 论文全部在编译器/映射器层**（DAC'25 Adora/Rewire、TCAD'25 数据
  复用），没有新硅片——领域焦点已从架构转向工具链；
- 架构级（无流片）：Plasticine 28nm 113 mm²/1 GHz/49 W（16×8 = 64 PCU + 64 PMU，
  ISCA'17）及其后继 SARA/DSAgen/Riptide；
- 通信域 CGRA 历史锚点：ADRES（imec SDR 基带）、MorphoSys（ISCA'00，为无线基带设计）。

### 8.1 Onyx 对象概览与 GPCP 对比

| | **GPCP CGRA** | **Onyx**（Stanford，JSSC'25/VLSI'24） |
|---|---|---|
| 架构 | 16 PE × 32-bit 定点 MAC，spad 全交叉开关 + IMEM，**逐拍微码** | PE tile + MEM tile 阵列（可组合存储原语、应用特化 PE、GLB），**编译器映射**（Halide/MLIR） |
| SoC 形态 | CVA6（RISC-V）+ CGRA | 主处理器 + CGRA + GLB + SerDES |
| 节点 / 状态 | Nangate45 学术库，**pre-layout** | **GF 12nm FinFET，已流片** |
| 频率 | 1,053 MHz（pre-layout 估计） | **CGRA 970 MHz** / 处理器 500 MHz |
| 峰值算力 | ~8–34 GOPS（INT32，16 PE） | **571 INT16 GOPS** |
| 能效 | iEDA 估算 ~336–672 GOPS/W（toggle 0.1，软） | **756 GOPS/W**（INT16，实测） |
| 面积 | 逻辑 0.0685 mm²（含存储 0.27–2.8 mm²） | **CGRA 8.28 mm²**，整芯 **23.00 mm²** @12nm |
| 负载 | LTE/NR/WiFi **17 条 L1 链** | 稀疏+密集张量、图像处理、ML |

出处：Onyx = JSSC 2025（DOI 10.1109/JSSC.2025.3604724）/ VLSI 2024（12nm、970 MHz、
571 GOPS、756 GOPS/W、CGRA 8.28 mm²、整芯 23 mm²、0.78 V 核压）；对前代 CGRA（Amber）
图像/ML 的 EDP 降低 76%/85%，稀疏 kernel 对 CPU（带稀疏库）EDP 好 565×。

### 8.2 归一化到 45nm 后的对比与结论

- **面积**：Onyx CGRA 8.28 mm²@12nm FinFET → 45nm 平面工艺约 **×12–14**（FinFET 密度
  优势）≈ **99–116 mm²**。GPCP 逻辑 0.0685 mm²（含存储 0.27–2.8 mm²）——**差 3 个
  数量级**。这不是"谁做得好"，而是规模定位完全不同：Onyx 数百个 PE/MEM tile +
  4.45 mm² 的 GLB，GPCP 只有 16 PE；
- **峰值算力**：571 vs ~8–34 GOPS → **17–70×**，同样主要是规模差；
- **能效（最有意思的一项）**：Onyx 实测 756 GOPS/W（INT16）；GPCP 估算 336–672
  GOPS/W（INT32，iEDA toggle=0.1，**软数据**）。若 GPCP 估算可信，则 **16-PE 定点
  小阵列的能效与 12nm 先进 CGRA 同一量级**——这印证了 CGRA 架构的共性：算力密度
  随节点增长，能效主要由架构（数据复用/互连）决定；
- **可重构粒度**：Onyx 是 kernel 级（编译器把 DFG 映到 PE/MEM 网络，配置驻留）；
  GPCP 是**逐拍**微码——GPCP 的粒度更细，但单核算力与工具链成熟度差距巨大；
- **域**：Onyx 面向稀疏/密集张量 + ML + 图像；GPCP 面向通信 L1 协议链。

### 8.3 对 GPCP 的启示

1. **规模与节点是主要差距**：Onyx 的 571 GOPS 来自"数百 tile + 12nm FinFET + 500 人组
   级工程"；GPCP 的 16 PE@45nm 在算力上不可比，也不需要可比——GPCP 的定位是
   **0.3 mm² 覆盖 17 条协议链**的轻量 L1；
2. **Onyx 的"可组合存储原语"**（压缩存储/流式/消除无效计算）与 GPCP 的 spad 交叉开关
   问题同构——数据通路原语化、编译器驱动的访存优化是两边共同的方向；
3. **能效验证**：GPCP 需要一次实测（FPGA/流片）才能把 336–672 GOPS/W 的估算变成
   可与 756 GOPS/W 同台的数据；
4. **工具链**：Onyx 背后是 Halide/MLIR 编译栈，GPCP 是自研微码编译器——成熟度差距
   与 docs/15 的映射质量基线一致。

## 9. 通信算子级对比（加速差异）——本项目最核心的对比表

把对比下沉到**算子**层：每个通信算子给出 GPCP CGRA / CVA6 的实测周期（`compare_all.csv`）、
频率校正后的**实际时间**（CGRA 1,053 MHz vs CVA6 264 MHz，见 docs/22 §9），以及研究侧
处理器在同一算子上的公开数字。

### 9.1 GPCP 算子级加速差异（实测周期 + 时间校正）

| FFT4096（OFDM 解调） | 334,050 | 9,013,402 | **27.0×** | 317 µs | 34.1 ms | **107×** | 规则蝶形数据流 |
| FFT4096（OFDM 调制） | 922,846 | 9,540,227 | 10.3× | 876 µs | 36.1 ms | **41×** | 同上 |
| MMSE 均衡（nr_mimo） | 23,440 | 21,759 | 0.93× | **22.3 µs** | 82.4 µs | **3.7×** | 小矩阵+控制 |
| Turbo 译码 | 2,789,752 | 2,750,386 | 0.99× | 2.65 ms | 10.4 ms | **3.9×** | 迭代+交织 |

### 9.3 三个可比结论

1. **"规则算子大加速"是阵列/向量架构的普遍规律**：Ara 对自身标量核在 CE 上加速
   78–182×，GPCP 在 FFT 上对 CVA6 加速 27×——同一现象；反过来 Ara 与 GPCP 都
   在控制重算子上获益有限（GPCP 相关 0.96×、Turbo 0.99×）。**CGRA/向量化的收益
   边界由算子的规则性决定，不由工艺决定**。
2. **规模差一个量级，定位不同**：Ara 16-lane 是 64-bit 浮点向量机（0.68 mm²@22FDX，
   12.31 µs 做 16×16 MMSE）；GPCP 是 16 个 32-bit 定点 PE（22.3 µs 做整条
   mimo_equalise）——算子口径不同，但**面积差 ~10×、频率同档**，GPCP 的单位面积
   时延预算并不差。
3. **与专用 ASIC 的差距 = 吞吐档位**：BayesBB/UniDec 用全展开流水线拿到 Gb/s 级
   吞吐，GPCP 是逐拍重构的 µs 级链路处理——两者的差距不是"设计好坏"，而是
   "可重构通用性 vs 专用吞吐"的定位差（GPCP 面积小 2 个数量级）。

### 9.4 数值级对比的缺口

- Ara 的 12.31 µs 是 **16×16 窗口**的 MMSE CE；GPCP 的 22.3 µs 是**整条 mimo_equalise**
  （均衡+硬判，2 层×180 RE）。同尺寸归一需要取 GPCP 的矩阵维度重跑——这是把
  本文从"平台级"升级到"数值级"的唯一剩余工作量；
- BayesBB 的 1.61 ms 是 128×128 cell-free 全链，与 GPCP 的 2×2/4×4 场景不可直接比。
