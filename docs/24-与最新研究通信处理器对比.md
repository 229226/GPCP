# 24 — 与最新研究通信处理器的对比（BayesBB / Ara BSoC / NUS PACE）

> 目的：`docs/22` 的对比锚点是**顺序 CPU**（CVA6，264 MHz @45nm）。本文把对比对象换成
> **最新研究中的通信处理器**——① 研究级可编程基带两条路线（专用 ASIC / 向量核），
> ② **同架构 CGRA**（NUS PACE/HyCUBE，硅片实测）——回答"GPCP 的 CGRA 在研究前沿里
> 处于什么位置"。
> 方式：文献指标 + 节点归一化（不动 RTL，1 天可复核）。
> 数据来源见各表脚注；GPCP 侧数字与 `docs/08` / `docs/22` 完全同源。

## 2. 归一化方法（粗粒度，只用于数量级）

- **面积**：`面积 × (L_target / L_ref)²`。40nm→45nm：×1.27；22nm→45nm：×4.18。
- **频率**：22FDX 对 45nm 通用库约 **1.5–2×**（FD-SOI 且先进两代）；40nm 对 45nm 约 1.1×。
- 声明：这是**线宽比例归一**，不含库风格/电压/双均差异，只能支撑数量级结论，
  不能替代同节点重综合。

## 3. 归一化到 45nm 后的面积 / 频率

| | GPCP CGRA | BayesBB | Ara (4-lane) | Ara (16-lane) |
|---|---:|---:|---:|---:|
| 原始面积 | 0.0685 mm²（逻辑） | 19 mm² @40nm | 0.68 mm² @22FDX | 2.13 mm² @22FDX |
| **归一化到 45nm** | 0.0685 mm² | **≈24 mm²** | **≈2.8 mm²** | ≈8.9 mm² |
| 归一化频率 | 1,053 MHz | — | ≈700 MHz（÷1.8 估） | ≈580 MHz |
| 归一化功耗 | 23.8–32.1 mW | — | 259 mW | — |

**面积数量级**（含存储口径 GPCP 取 0.27–2.8 mm² 区间）：

- BayesBB ≈ 24 mm²@45nm → 是 GPCP 的 **~69×**（最小口径）/ ~8.6×（现状交叉开关口径）。
- Ara 4-lane ≈ 2.8 mm²@45nm → 是 GPCP 的 **~8×**（同口径）；但 Ara 是 4 条向量 lane
  （每 lane 有 ALU/MUL/FPU + VRF），单核算力远高于 16 个 GPCP PE。

**频率**：GPCP 的 1,053 MHz 与 Ara 归一化后的 ~700 MHz 同一档——CGRA 短路径阵列
并不比向量核慢；真正拉开差距的是**每周期算力**（Ara 16-lane 峰值 32 DP-GFLOPS vs
GPCR 16 PE × 每 PE 每 2 拍一次 MAC）。

**功耗**：Ara 259 mW（跑 256×256 矩阵乘）vs GPCP 23.8–32.1 mW——GPCP 的绝对功耗低
一个量级，但这是"16 PE 小阵列"与"4 lane 向量机"的规模差，不是能效差；能效要归一到
相同吞吐才有意义（见 §5 缺口）。

## 4. "可配置"的三种粒度——三条路线的本质差异

| | 重构发生在 | 重构时间常数 | 换算法的代价 |
|---|---|---|---|
| **GPCP CGRA** | **每一拍**（微码逐拍变） | 0 拍（微码已驻留 IMEM） | 写新微码（分钟级，工具链自动生成） |
| **BayesBB** | 架构级参数（并行阶/码字参数） | 毫秒–秒级（重配置流水线拓扑） | 重综合（月级）或受限参数空间 |
| **Ara BSoC** | 指令级（RVV + 未来自定义指令） | 0（软件换函数） | 写 C/内建函数 |

- BayesBB 的"可配置"是**编译/部署期**的：全展开流水线一旦投片，支持 LDPC/polar/MIMO-BP
  的参数空间，但不支持任意新算子；
- Ara 的"可配置"是**软件期**的：任意 C 代码都能跑，但每拍吞吐受限于向量宽度；
- GPCP 的"可配置"是**数据通路级**的：16 PE 的互连/操作数/操作每拍可变——这是 CGRA
  相对两者的唯一结构优势，代价是每 PE 算力小、需要编译器把 kernel 映成微码。

## 5. 工作负载对齐的缺口（诚实标注，引用本文必须带上）

1. **规模不同**：BayesBB 面向 **128×128 cell-free mMIMO**（9.6 Gb/s 用户吞吐），
   GPCP 场景是 2×2/4×4 MIMO 的 LTE/NR/WiFi 链——**不能直接比吞吐**，只能比
   "单位面积的灵活性"与"单位算力的时延预算"。
2. **Ara BSoC 的 kernel cycle 只在论文图 1**（16×16/32×32 矩阵、VLEN 512–4096），
   正文无数值——精确对比需要联系作者或复现（Ara RTL 开源，是可做项）。
3. **GPCP 每场景的 TB 比特数**尚未从生成器推导，因此"吞吐（Gb/s）× 能效（pJ/bit）"
   的定量对比暂缺——这是本文最大的数据缺口，补齐方法：解析 `tools/*_ce.py` 各场景
   的 `cfg.derived`（NRE × qm × 符号数），除以 `compare_all.csv` 的周期数。
4. BayesBB 频率/功耗未公开检索到，需 JSSC 原文补齐。

## 6. 定位结论

- **GPCP CGRA 的位置**：面积效率极高的**轻量逐拍可重构 L1**——0.0685 mm² 逻辑
  （0.27–2.8 mm² 含存储）就覆盖 17 条 LTE/NR/WiFi 链，面积比 BayesBB 小 1–2 个数量级，
  比 Ara 向量核小 ~8×，而频率与其归一化值同档。
- **与 BayesBB 的差距 = 专用化的差距**：BayesBB 用 220× 的面积换 9.6 Gb/s 的固定
  消息传递吞吐；GPCP 不追求那个吞吐档位，追求的是"一块 0.3 mm² 的硅覆盖多标准多场景"。
- **与 Ara 的差距 = 并行宽度的差距**：Ara 的向量 lane 是成熟 64-bit FPU 流水线，
  GPCP PE 是 32-bit 定点 MAC——若对标 Ara 的浮点 LOW-PHY，GPCP 需要加宽 PE/加 lane；
  若保持定点 L1 定位，则 GPCP 的面积效率优于 Ara。
- **对 docs/22 结论的修正**：CPU（264 MHz）→ 研究级可编程基带（1 GHz 量级）的对比
  说明"通用顺序核"不是合适基线；**正确的基线是 Ara 这类向量核/轻量基带处理器**，
  这也是后续 kernel 移植实验（Ara RTL 开源）的价值所在。

## 8. 与同架构 CGRA 的对比（NUS PACE / HyCUBE）——最公平的参照

把对比对象从"其它架构"换成**同架构 CGRA**后，比较的不再是路线差异，而是**设计质量**。
NUS ECO Lab 的 **PACE（HotChips 2024）/ HyCUBE（A-SSCC 2019）**是目前最合适的参照：
同为"**RISC-V SoC 里的 CGRA**"，同为开源工具链生态（Morpher-v2，ICCAD'25），且**硅片实测**。

### 8.0 研究时间线：为什么 PACE 是"最新且可对比"的

- **硅片级**：HyCUBE 40nm（A-SSCC'19，753 MHz）→ **PACE 28nm（HotChips'24，360 GOPS/W，
  A*STAR IME 流片）**——这是目前**最新流片的 CGRA**；
- **2025 年的 CGRA 论文全部在编译器/映射器层**（DAC'25 Adora/Rewire、TCAD'25 数据复用），
  没有新硅片——领域焦点已从架构转向工具链；
- **架构级（无流片）**：Plasticine 28nm 113 mm²/1 GHz/49 W（16×8 = 64 PCU + 64 PMU，
  Stanford/MSRA，ISCA'17）——规模大三个数量级、面向数据分析，不面向通信；其后继
  SARA（ISCA'19）、DSAgen（ISCA'20）、Riptide（MICRO'22）同属"生成式空间架构"研究；
- **通信域 CGRA 的历史锚点**：ADRES（imec，SDR 基带平台）、MorphoSys（UCI，最初就是
  为无线基带设计的 ISCA'00 工作）。

结论：**PACE/HyCUBE 是"最新流片 + 同定位（RISC-V SoC 里的 CGRA）+ 有硅片数据"的唯一
交集**，作为 CGRA 对比对象是最优选择。

### 8.1 对象概览

| | **GPCP CGRA** | **PACE / HyCUBE**（NUS ECO Lab） |
|---|---|---|
| 架构 | 16 PE × 32-bit 定点 MAC，spad 全交叉开关 + IMEM | HyCUBE CGRA：无缓冲 NoC、**单周期多跳互连** |
| SoC | CVA6（RISC-V）+ CGRA + CLINT | RISC-V SoC（A*STAR IME 流片） |
| 节点 / 状态 | Nangate45 学术库，**pre-layout**（OpenSTA） | **40nm 硅片实测**（A-SSCC'19）；PACE 28nm（HotChips'24，IME） |
| 频率 | 1,053 MHz（pre-layout 估计） | **753 MHz**（实测 max，4 hops/cycle） |
| 能效 | iEDA 估算 23.8 mW @500 MHz（toggle 0.1，非实测） | **26.4 MOPS/mW、290 pJ/cycle（实测）**；比 Zynq FPGA 高 28.6×、Cortex-A7 高 26.5× |
| 系统能效 | — | PACE **360 GOPS/W**（28nm） |
| 编译器 | 自研微码编译器 | Morpher-v2 开源框架（WOSET'22/CODAI'23/ICCAD'25） |
| 负载 | LTE/NR/WiFi **17 条 L1 链** | IoT/边缘通用 kernel |

出处：NUS ECO Lab Chip Gallery（753 MHz / 26.4 MOPS/mW / 290 pJ/cycle / PACE 360 GOPS/W@28nm）；
A-SSCC 2019 论文（40nm、127× vs TI Sensortag IoT 平台）；HotChips 2024（PACE in RISC-V SoC）。

### 8.2 对比结论

1. **频率同一档**：HyCUBE 硅片实测 753 MHz@40nm；GPCP pre-layout 1,053 MHz@45nm
   （布线后约 550–680 MHz）。归一化后两者同档——**GPCP 的 16-PE 阵列在频率上不输**。
2. **能效对比存在方法论鸿沟，不能直接比数**：HyCUBE 是硅片实测（26.4 MOPS/mW），
   GPCP 是 iEDA toggle=0.1 的估算——若硬比，GPCP 16-PE 的标称算力（~8–16 op/拍）
   高于 HyCUBE（~7.65 op/拍），但**估算值不能作为能效优势的证据**；正确做法是
   GPCP 做一次同口径实测或 FPGA 原型。
3. **互连哲学正面对照——这是最有价值的发现**：HyCUBE 的核心创新是**无缓冲单周期
   多跳 NoC**（远端 FU 一拍直达，不占中间计算资源）；而 GPCP 的 spad 是**全交叉开关**
   （19 读/1216 写端口），正是面积最大单项（~2.6 mm²，见 docs/08 §3.2）。
   **HyCUBE 证明了多跳互连可以把交叉开关的面积问题解决掉**——与 docs/08 §3.3
   "硬件地址加扰 + 多端口 bank"的方向互补，是 GPCP 后续降面积的最直接参考。
4. **域定位不同**：PACE/HyCUBE 面向 IoT 通用 kernel（边缘加速），GPCP 面向**通信
   L1 全链**（17 条协议场景）——GPCP 的差异化在"协议域覆盖 + 逐拍重构"，这是
   HyCUBE 没有做的。
5. **工具链生态**：Morpher-v2 已发展为开源 CGRA 全栈（编译/RTL 生成/仿真/验证，
   ICCAD'25 "Building an Open CGRA Ecosystem"）；docs/15 已用它标定过映射质量
   （II=4 基线）。GPCP 的自研编译器有明确对标，但生态成熟度是短板。

### 8.3 对 GPCP 的三条可执行启示

1. **spad 交叉开关 → 多跳互连**：HyCUBE 与 docs/08 §3.3 的地址加扰实验指向同一
   结论——全交叉开关不可持续，多跳/分桶是正解，潜在收益 ~2.6 → 0.9 mm²；
2. **补一次实测能效**：FPGA 原型或 40nm 流片，把"23.8 mW 估算"变成可与
   26.4 MOPS/mW 同台比较的数据；
3. **编译器生态**：借鉴 Morpher-v2 的 ADL/RTL 生成/验证框架，补 GPCP 工具链的
   验证与文档短板。
