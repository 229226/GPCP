# 24 — 与最新研究中的 CGRA 架构通信处理器对比

> **2026-11-13 重做版。**
> 上一版把「Onyx / NUS PACE / Ara / BayesBB」当作对比对象，但它们**不同时满足
> "CGRA 架构 + 通信领域 + 最新研究"**：Onyx 是 CGRA 但跑 ML/图像；PACE/HyCUBE 是 CGRA
> 但定位 IoT 通用 kernel；Ara 是向量核（不是 CGRA）；BayesBB/UniDec 是通信专用 ASIC
> （不是 CGRA）。用它们回答「同架构通信处理器的设计质量」是错位的。
> 本版重新筛选，只保留**面向无线基带/L1 的 CGRA（含 CGRA 谱系的可重构阵列）**，
> 并且把对比下沉到**算子级**（用户要求的"加速差异"）。
>
> 方式：文献一手指标（已逐条核对 DOI / 会议 / 官方页）+ 节点归一化（仅数量级）
> + GPCP 侧 `build/proto/compare_all.csv` 实测周期。不动 RTL，可复核。
> GPCP 侧数字与 `docs/08`、`docs/22` 同源。

## 1. 筛选标准：什么才算「CGRA 架构的通信处理器」

| # | 硬标准 | 说明 |
|---|---|---|
| 1 | **字级可重构的 PE 阵列** | 有 PE/FU 阵列 + 配置上下文/上下文切换，排除纯硬连线流水线与纯向量核 |
| 2 | **负载是无线基带 / L1** | FFT/OFDM、MIMO 检测/均衡、信道估计、FEC 译码、波形调制、相关/同步 |
| 3 | **有硬件 PPA** | 硅片实测 / 流片 / 至少综合或 FPGA 原型，给出工艺、频率、面积或功耗 |
| 4 | **近期（2020 年后优先）** | 2024–2026 的硅片或原型为主，早期工作只作演进锚点 |

### 4.1 归一化方法与三条可比结论

节点从 12/16nm FinFET 折回 45nm 平面工艺，密度经验系数 **×10–14**（含 FinFET
密度优势），误差 ±40%，**只用于数量级判断**。

1. **规模差 1–3 个数量级，但"每 PE 算力"同档**：DAP 264 GMAC/s ÷ 256 核 =
   **1.03 GMAC/s/核**；GPCP 16.85 GMAC/s ÷ 16 PE = **1.05 GMAC/s/PE**。
   两者相差 ~2%——说明差距主要来自**阵列规模（16 vs 256）与工艺**，而不是单 PE 的
   架构效率。这是本文最干净的一个同维度结论（均按 1 MAC/拍/PE 的峰值口径）。
2. **能效同量级，但置信度不对称**：DAP 507 GMACs/J 是**硅片实测**；GPCP
   336–498 GMACs/J 是 iEDA toggle=0.1 的**估算**——不能作为能效优势的证据，
   只能说明"没有数量级偏离"。GPCP 需要一次 FPGA/流片实测才能同台比较。
3. **频率口径**：GPCP 1,053 MHz 是 pre-layout 理想时钟；硅片 CGRA 实测落在
   170–800 MHz（DAP ~620、清华 800、Tampere 170 FPGA）。按 45nm 布线后
   0.5–0.65× 折算，GPCP 约 **550–680 MHz**，与清华 CGRA 800 MHz@28nm 同档。

### 5.1 GPCP 侧：全部算子实测（`compare_all.csv`，131 行 / 17 场景）

### 5.2 决定性发现：加速差异由「有没有写专用微码」决定，不是算子固有规则性

按 `impl` 字段分组（该字段标记该算子是否有 CGRA 专用微码实现）：

| CGRA 专用微码实现 | 样本 | 周期比均值 | 范围 |
|---|---:|---:|---|
| `fft4096` | 17 | **23.58×** | 10.14–30.84× |
| `prach_corr` | 3 | **10.95×** | 9.87–11.52× |
| `ldpc_bg2_zc20` | 7 | **2.30×** | 1.00–2.55× |
| `dft256_cgra` / `sss_corr` / `pss_corr` / `polar9@512` | 4 | 1.2–1.65× | — |
| **（无专用实现，走标量回退）** | **37** | **1.19×** | 0.94–4.69× |
| `turbo_k104` / `mmse_2x1` / 各类 `ref_*` | 15 | ≈1.00× | 0.92–1.02× |
| `polar_node@512` | 2 | **0.54×** | 0.53–0.55× |
| `cell_search_cgra` | 2 | **0.24×** | 0.24–0.25× |

**这修正了上一版的一个错误归因**：上一版把"相关 0.24×"解释为"算子控制重、
CGRA 天然不适合"。实际上同一个 `correlate` 算子，`prach_corr` 有专用微码 →
**11.5×**，而 `cell_search_cgra` 有微码但写得差 → **0.24×**（比 CPU 慢 4×）。
所以真正的瓶颈是**映射/微码质量**，不是算子类别。这与 JSA'24 综述的判断一致：
CGRA 在基带的瓶颈是**编译器映射与访存**，而非 PE 算力。

> 对论文写作的直接影响：不能把"某算子加速低"写成"CGRA 架构不适合该算子"，
> 应写成"该算子当前映射未优化"，并把它列为后续工作（§7）。

### 5.3 与研究侧 CGRA 的算子级对照

| 算子 | GPCP（16 PE，45nm pre-layout） | DAP（256 核，12nm 硅片） | 清华 JSSC'20（64 PE，28nm 硅片） |
|---|---|---|---|
| **FFT** | FFT4096 解调 293,559 周期 = **279 µs @1.053GHz**；周期加速 30.8×（对 CVA6） | 256 点 FFT：**4.41 Gsample/s、53.96 nJ/FFT、13 PE** | 支持 FFT（点数/周期未公开） |
| **OFDM 整链** | 整链 `nr_mimo` 408,874 周期 = **388 µs** | **46.46 Gb/s、19 PE**（FIR+FFT+全相关） | 支持滤波/FFT，无整链数字 |
| **MIMO 检测 / 均衡** | MMSE 2×1：23,440 周期 = **22.3 µs**，对 CPU 0.93× 周期（时间 3.7×） | MMSE **1.95 Gmatrix/s、178.5 nJ/matrix、20 PE**；QR 4×4 用 12 PE | CHD/WeJi/SD/ZF/LMMSE，4×4~128×8，1.64–2.92 Gb/s/W |
| **FEC 译码** | LDPC 2.30× / Turbo 1.00× / Polar 0.54×（周期） | 不覆盖 | 不覆盖 |
| **相关/同步** | PRACH 11.5×；cell search 0.24×（周期） | OFDM 内含 all-correlation | ADRES（2008）支持相关/CFO |
| **重构粒度** | **逐拍微码**（最细） | kernel 级换挡 **<1 µs / 数百周期** | 上下文切换（自适应上下文 −67%） |

**三条同维度结论：**

1. **PE 预算几乎相同，覆盖面差很多**：DAP 做 256 点 FFT 用 13 PE、OFDM 整链 19 PE、
   MMSE 20 PE；GPCP 用 16 PE 做 FFT4096 + 整条 17 条 L1 链。相近 PE 预算下，
   **GPCP 的差异化是"协议域覆盖 + 逐拍重构"，DAP 的差异化是"单算子极限吞吐"
   （264 GMAC/s）**。两者不是同一优化目标。
2. **FFT 是两边共同的"甜点算子"，但不可直接比数**：GPCP 4096 点 279 µs，
   DAP 256 点 4.41 Gsample/s（≈58 ns/FFT）。点数差 16×、PE 数差 16×、
   节点差 3 代、pre-layout vs 硅片——硬比没有意义。可比的是**加速机制**：
   两者都靠蝶形数据流的空间映射 + 无冲突访存（DAP 用 bit-reverse 时/空访问切换，
   GPCP 用 `fft4096` 专用微码），这解释了 23.58× 与 4.41 Gsample/s 是同一现象。
3. **控制重算子的收益边界是跨架构一致的**：DAP 的 QR/回代/MMSE 被正文明确称为
   "迭代且计算密集、吞吐更低"（MMSE 20 PE 只换到 1.95 Gmatrix/s，远低于
   FIR 的 252 GMAC/s）；GPCP 的 MMSE/Turbo/Polar 也落在 0.5–1.0× 周期。
   **阵列/可重构架构的收益边界由"能否填满空间数据流"决定，与工艺无关**——
   这是和 CGRA 文献对话时最稳的论点。
4. **"覆盖多少算子"是比"单算子多快"更贴近 GPCP 的指标**：DAP Table VII 明确列出
   **17 个已映射 kernel**（四款可编程架构里最多，其余为 4–5 个），GPCP 覆盖
   **17 条 LTE/NR/WiFi L1 协议链**。两者都把"广度"当作价值主张，而
   BayesBB / ISSCC 专用检测器只覆盖 1–2 个算子。GPCP 应把
   "16 PE 覆盖 17 条链"作为与这些工作对话的主指标，而不是去拼单算子 Gb/s。

## 6. 对 GPCP 的三条可执行启示

1. **补映射，不是补 PE**：§5.2 显示 37 个"无专用微码"算子平均只有 1.19× 周期比，
   而 `cell_search_cgra` 甚至 0.24×。按性价比排序，先重写
   `cell_search` / `polar_node@512` / `turbo_k104` / `mmse_2x1` 的微码，
   比扩大阵列更能改善整链。目标：把最差算子从 0.24× 提到 ≥1×，
   `lte_cell_search` 整链（当前 0.245×，唯一 CPU 占优场景）即可翻盘。
2. **换挡粒度可以直接对标 DAP**：DAP 用"数百周期 / <1 µs 换 kernel"证明
   细粒度重构可商用；GPCP 的逐拍微码更激进，应在文档里把它写成**架构优势**
   并给出实测切换开销（目前未测，是缺口）。
3. **spad 交叉开关**：JSA'24 综述里 HyCUBE 的"无缓冲多跳单周期互连"、
   清华 JSSC'20 的"分布式多交互存储（访存 −82%）"、DAP 的"FU 间单周期直连"
   都指向同一结论——全交叉开关不可持续。与 `docs/08 §3.3`（地址加扰 +
   多端口 bank，2.6 → ~0.9 mm²）方向一致，可作为该优化的外部佐证。

## 7. 引用口径与数据缺口（对外引用必须带上）

| 限制 | 说明 |
|---|---|
| **状态不对称** | GPCP 是 Nangate45 学术库的 **pre-layout 综合 + OpenSTA 理想时钟**；对比对象多为**流片实测**（12/16/28nm）或 FPGA 原型。绝对值不可并列，只能比数量级与比值。 |
| **功耗是估算** | GPCP 23.8/32.1 mW 来自 iEDA toggle=0.1，**不是实测**；336–498 GMACs/J 因此只是"同量级"提示，不能写成能效优势。 |
| **CPU 频率校正** | 3.99× 因子来自 CVA6 全核 OpenSTA 264 MHz（依赖手工缓冲树，真实 P&R 可能 ~300 MHz → 因子 3.5×，`nr_mimo` ~78×）。 |
| **TCAS-I'26 缺算子数据** | 56 Gb/s / 0.9 ms 是**链路级**指标，无逐算子周期，无法进入 §5 的算子表；面积/频率/功耗公开摘要未给。 |
| **DAP Table V 口径** | 效率列对 FFT/QR/MMSE 是 nJ 能耗、对 FIR/GMM 是 GMACs/J；"所需 PE"不含路由 PE。 |
| **节点归一化粗糙** | 12/16nm FinFET → 45nm 平面按 ×10–14 估，误差 ±40%，仅数量级用。 |
| **HyCUBE 双口径** | 综述表 28nm/704 MHz/115 mW/2.9 mm²；NUS Chip Gallery 40nm/753 MHz。两者不是同一颗/同一档，引用时须注明来源。 |
| **非 CGRA 路线边界** | BayesBB（40nm 19 mm²、9.6 Gb/s、1.61 ms）、UniDec、Ara 向量核、RISC-V 众核（12nm 66.3 Gb/s / 5.5 W）代表"非 CGRA 的灵活性解法"，它们是**路线竞品**，不是同架构对照，本文只用其界定上界。 |

### 7.1 把本文升级为"数值级对比"还差什么

1. GPCP 侧按 DAP Table V 的口径补测：256 点 FFT 的 Gsample/s、OFDM 整链 Gb/s、
   MMSE 的 Matrix/s 与每算子占用 PE 数 —— 有了这三个数就能与 DAP 真正并表；
2. 从 `tools/*_ce.py` 推导每场景 TB 比特数 → GPCP 吞吐（Gb/s），与
   TCAS-I'26 的 56 Gb/s、BayesBB 9.6 Gb/s 同尺度；
3. 索取 TCAS-I'26 原文的逐算子表与芯片微照片面积（当前只有摘要）。
