# 夜间批次计划（2026-11-05 夜 → 11-06 晨）

一个晚上的目标不是"做完 P4/P5"，而是**用无人值守时间换取可验收的增量**：每个任务
自带模型 + 硬件 + checker 三件套，独立提交，失败隔离。开发任务由 Agent 逐个推进；
与开发无关的长跑放在独立 git worktree 的快照里跑，互不干扰。

## 1. 原则

1. **失败隔离**：一个任务失败只写 `build/nightly/failures.txt`，不阻塞后续任务。
2. **原子提交**：每个任务 = 一次提交，提交信息带验收数字；工作区必须干净才算完成。
3. **自动验收**：每个任务至少一条 `make run-*` + 一条模型 selftest；收尾跑
   `bash tools/verify.sh slow --force`（规则见 `AGENTS.md` §9）。
4. **不猜**：仿真通不过就停在原地记录，不把"看起来对"写成 PASS。

## 3. 夜间长跑（`tools/nightly.sh`，与开发隔离）

在 `build/nightly/wt-*` 的 **git worktree 快照**里执行，避免被开发中的改动污染：

- **A 多种子回归**：核心 8 门 × seed 1/2/3（捕获种子相关的偶然通过）。
- **B SNR 扫描**：`run-pdsch-full` / `run-pusch` / `run-sib1` / `run-pdcch` 在
  -5/0/5/10/15/20 dB（定位各链路的瀑布拐点，喂给 `nr_la.py` 的 BLER 模型）。
- **C 全量留档**：`bash tools/verify.sh slow --force`。
- **D Linux 长引导**：`make -C sim/soc linux`（10^8 周期，观察是否推进到用户态）。

产出 `build/nightly/<ts>/report.md`：每行「门 / 参数 / 结果 / 周期」，失败行标红；
`failures.txt` 汇总非零退出。整夜跑不完就按 A→B→C→D 顺序截断，先保证 A/B。
