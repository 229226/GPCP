# GPCP 路线图与验收标准

> 原则：每个里程碑都必须有**可运行的仿真 + 可自动比对的黄金模型**，再往上叠加复杂度。

## M0 — CGRA 微架构闭环（已完成）

交付：
- `rtl/cgra/`：4×4 PE 阵列 + 全局定序器 + AXI4-Lite 从口 + 指令存储器；
- `tools/cgra.py`：微码汇编器 + kernel 库（matmul4x4、fir16）+ 自动比对；
- `sim/cgra/`：Verilator 模型（CPU 由 C++ 总线 BFM 扮演）；
- 文档：架构选型、ISA/寄存器映射、路线图。

验收（已通过）：
- `python3 tools/cgra.py test` → `ALL TESTS PASSED`；
- matmul4x4：16 个 PE 的 `acc` 与黄金模型逐位一致；
- fir16：16 个 PE 的移位数据 `r1` 与累加结果 `acc` 与黄金模型一致；
- 注入错误后测试能失败（检查器非空转）。

## M1/B2 — 真实 RISC-V 核驱动 CGRA（已完成）

> 实际执行时选择了 CVA6（B 方案）而非 Ibex：核更大但一步到位，后续跑 Linux 不用换核。

内容（已完成）：
1. CVA6（`cv64a6_imafdc_sv39`，RV64GC + WT cache + AXI 64-bit）接入自研 SoC；
2. SoC 侧 AXI 从机：512 KiB RAM（支持突发）+ CGRA 寄存器窗口 + 退出寄存器；
3. 裸机程序 `sw/soc/cgra_bm.c`：装载微码 → 预装载 PE → 启动 → 轮询 → 回读 16 个 acc；
4. 结果与 Python 黄金模型逐位一致，**2058 周期**完成；
5. 代码：`rtl/soc/gpcp_soc.sv`、`sim/soc/`、`sw/soc/`、`docs/05-soc-b2.md`。

验收（已通过）：
- `make -C sim/soc run` → `[ OK ] CVA6 -> CGRA matmul matches the golden model`；
- 交叉编译（`riscv64-unknown-elf-gcc`，RV64GC，无 libc）通过；
- 验证了 CVA6 配置、AXI 字节 lane、cache line 突发三条最容易出错的路径。

遗留（转入 B3）：
- 无 UART/中断、RAM 仅 512 KiB、单 outstanding AXI。

## M2/B2.5 — 裸机 L1 数据面 + DMA 双缓冲（已完成）

1. scratchpad 扩到 64 banks / 8 KiB（双页），新增 `LD/ST` 与页选择；
2. 描述符驱动拷贝引擎（RAM↔scratchpad、2D `stride/row`、页隔离、CPU 优先仲裁）；
3. 四个 L1 kernel（FFT-16 / LS / MMSE / LDPC-CN）+ 三个 DMA 用例（阵列级 `dma_pingpong`、
   SoC 级轮询版 `dma_bm`、SoC 级中断版 `irq_bm`）全部与 Python 定点黄金模型逐位一致；
4. 完成中断 + 最小 PLIC：CGRA `irq_o` → PLIC 源 1 → CVA6 机器外部中断，CPU 用 `wfi`
   等 slot 完成；
5. 突发拷贝（64-bit beat、8 拍/描述符、双写口）+ 描述符环（环在 RAM、引擎自取、
   自写状态、`RING_DONE` 进度计数）：1024 字线性拷贝 1.18 周期/字；
6. 验证：`python3 tools/cgra.py test`、`make -C sim/soc run`、`run-dma`、`run-irq`、`run-ring`。

遗留（转入 M3/M5）：
- 引擎是内部 64-bit 主口，不是真 AXI INCR 突发；scratchpad 深度只有 2 页；FFT 仍为 16 点。

## M2/B3 — CVA6 跑 Linux（下一步）

1. RAM 扩到 ≥64 MiB（换成稀疏/分段 RAM 模型，避免 Verilator 分配爆炸）；
2. 加 UART（16550）+ PLIC 中断 + CLINT 定时器；
3. BusyBox initramfs 启动，跑用户态程序访问 CGRA（`/dev/mem` 或 UIO）；
4. 验收：`uname -a` 输出 RV64、用户态读取 CGRA ID 寄存器成功。

## M2/B4 — 协议栈与 PHY 骨架（双模）

1. srsRAN_Project（NR）/ srsRAN_4G（LTE）作为**接口与算法参考**，抽出 PHY kernel 清单；
2. 在 CGRA 上实现：复数 MAC、FFT-16/64、PSS 相关、信道估计（LS）；
3. QEMU 自定义 CGRA 设备模型（与 RTL 同一 ABI），用于快速软件迭代；
4. free5GC 联调：gNB（仿真）→ N3 → UPF。

验收：
- NR 下行 SSB + PDSCH 一条链路在 CGRA 模型上产生与 srsRAN 参考一致的星座/软比特（BER 对齐）；
- LTE PSS/SSS 检测在 CGRA 模型上跑通；
- 端到端 ping / iperf（仿真）。

## M3 — 规模扩展与自动化映射

1. 8×8 / 16×16 阵列 + scratchpad + 双发射 + DMA 描述符环；
2. CGRA-ME 架构探索报告（面积/频率/利用率）；
3. MLIR（CGRA-Flow 路线）自动映射，替代手工微码；
4. LDPC / Polar 译码 kernel；
5. 性能模型：周期级 + 带宽级。

验收：
- 自动映射生成的微码与手工微码功能一致；
- 给定 100 MHz / 4T4R 预算，给出周期与带宽报告。

## M4 — FPGA 原型（可选，需硬件）

1. 目标板卡（Zynq UltraScale+ / 国产 FPGA）；
2. 时序收敛、DDR、JESD204B 前端；
3. 与真实 RF 子板联调。

## 风险与决策点

| 决策点 | 时点 | 选项 |
|---|---|---|
| CPU 核定型 | M2 前 | CVA6 / Rocket / 双核（大核跑协议、小核跑实时） |
| CGRA 规模与位宽 | M2 前 | 8×8 int16 vs 8×8 bf16 vs 混合 |
| 编译路线 | M2 末 | 手工微码 vs MLIR 自动映射 |
| 是否上 FPGA | M3 末 | 依据经费与验收指标 |
