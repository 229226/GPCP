# GPCP 路线图与验收标准

> 原则：每个里程碑都必须有**可运行的仿真 + 可自动比对的黄金模型**，再往上叠加复杂度。

## M0 — CGRA 微架构闭环（已完成）

交付：
- `rtl/cgra/`：4×4 PE 阵列 + 全局定序器 + AXI4-Lite 从口 + 指令存储器；
- `tools/cgra.py`：微码汇编器 + kernel 库（matmul4x4、fir16）+ 自动比对；
- `sim/cgra/`：Verilator 模型（CPU 由 C++ 总线 BFM 扮演）；
- 文档：架构选型、ISA/寄存器映射、路线图。

验收（已通过）：
- `python3 tools/cgra.py test` → `ALL TESTS PASSED`；
- matmul4x4：16 个 PE 的 `acc` 与黄金模型逐位一致；
- fir16：16 个 PE 的移位数据 `r1` 与累加结果 `acc` 与黄金模型一致；
- 注入错误后测试能失败（检查器非空转）。

## M1 — 真实 RISC-V 核驱动 CGRA（下一步）

目标：把 C++ 总线 BFM 换成**真的 RISC-V 核**，CPU 跑裸机程序，通过 AXI 下发任务。

内容：
1. 引入 Ibex（Apache-2.0）最小 SoC：RV32IMC + 片上 RAM + UART + CGRA AXI-Lite；
2. 启动代码 + 链接脚本 + `riscv64-unknown-elf-gcc` 工具链（已安装）；
3. 驱动：`cgra_run(task)`，中断/轮询两种完成方式；
4. 端到端用例：CPU 从 UART 接收参数 → 装载 kernel → 运行 → 打印结果；
5. Verilator 里跑通 `hello_cgra` 与 `matmul4x4`。

验收：
- `make -C sim/soc run` 输出与 M0 黄金模型一致；
- 单次任务下发开销（周期数）有统计；
- 代码在 `sw/`，RTL 在 `rtl/soc/`。

## M2 — 协议栈与 PHY 骨架（双模）

目标：CPU 侧能跑 Linux 用户态协议栈，CGRA 侧承担可验证的 PHY kernel。

内容：
1. CVA6（RV64GC）Linux 启动（仿真，QEMU 先行、RTL 后补）；
2. srsRAN_Project（NR）/ srsRAN_4G（LTE）作为**接口与算法参考**，抽出 PHY kernel 清单；
3. 在 CGRA 上实现：复数 MAC、FFT-16/64、PSS 相关、信道估计（LS）；
4. QEMU 自定义 CGRA 设备模型（与 RTL 同一 ABI），用于快速软件迭代；
5. free5GC 联调：gNB（仿真）→ N3 → UPF。

验收：
- NR 下行 SSB + PDSCH 一条链路在 CGRA 模型上产生与 srsRAN 参考一致的星座/软比特（BER 对齐）；
- LTE PSS/SSS 检测在 CGRA 模型上跑通；
- 端到端 ping / iperf（仿真）。

## M3 — 规模扩展与自动化映射

1. 8×8 / 16×16 阵列 + scratchpad + 双发射 + DMA 描述符环；
2. CGRA-ME 架构探索报告（面积/频率/利用率）；
3. MLIR（CGRA-Flow 路线）自动映射，替代手工微码；
4. LDPC / Polar 译码 kernel；
5. 性能模型：周期级 + 带宽级。

验收：
- 自动映射生成的微码与手工微码功能一致；
- 给定 100 MHz / 4T4R 预算，给出周期与带宽报告。

## M4 — FPGA 原型（可选，需硬件）

1. 目标板卡（Zynq UltraScale+ / 国产 FPGA）；
2. 时序收敛、DDR、JESD204B 前端；
3. 与真实 RF 子板联调。

## 风险与决策点

| 决策点 | 时点 | 选项 |
|---|---|---|
| CPU 核定型 | M2 前 | CVA6 / Rocket / 双核（大核跑协议、小核跑实时） |
| CGRA 规模与位宽 | M2 前 | 8×8 int16 vs 8×8 bf16 vs 混合 |
| 编译路线 | M2 末 | 手工微码 vs MLIR 自动映射 |
| 是否上 FPGA | M3 末 | 依据经费与验收指标 |
