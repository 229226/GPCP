## cgracc 编译器增量开发（会话：继续开发编译器）

### 新增能力：整数位运算（Q0 / i32）
- `cgracc/frontend/lower.py` 新增 `bit_and` / `bit_or` / `bit_xor` /
  `shl_bits` / `lshr_bits` / `ashr_bits`，统一要求操作数 Q0。
- 关键事实（由硬件决定）：ISA 只有 `and`/`xor`，没有 `or`；`shr` 是**算术**右移。
  - `or` 用 `a + b - (a & b)` 模 2^32 恒等式合成（3 条指令）。
  - `lshr` 必须 `shr` 后再与 `(1<<(32-k))-1` 掩码。
  - `shl`/`lshr`/`ashr` 的位移量只能来自指令 `imm`，运行期位移量明确拒绝。
- 区间收紧：`x & 正常量` → `[0, mask]`；`x ^ -1` → `[-1-hi, -1-lo]`，
  下游 16 位乘法因此仍可定标。
- `frontend/llvm.py` 增加 `and/or/xor` 与 `shl/lshr/ashr` 分派；`lshr i64`
  拆字分派必须先于通用移位分派（已调整顺序）。

### 新增能力：无符号比较支持负区间
- 不能"翻符号位再相减"：异号时差值越过 32 位边界，`sub` 回绕会把序判反。
- `lower.py::ucmp` 按符号位分流：异号直接看符号位，同号才做 `sub >> 31`；
  `le = lt | eq`（掩码加法恒等式），`gt/ge` 取反。

### 修复：`--ll` 语义
- `llvm.py::_ir_text`：`--ll` 指向已存在文件时直接读取并跳过 clang；
  `--src` 可省略；CLI 给出明确错误。纯 IR 路径可在无 clang/WSL 环境开发。

## GPCP 侧 compiler/runtime 修改（用户授权改 GPCP 的 compiler 部分）

### HAL 传输策略（`GPCP/compiler/targets/gpcp_4x4/runtime/cgracc_target.c`）
- 查 RTL 确认：spad 有 host MMIO 读写窗口（0xA000 + word*4，`cgra_spad_swz` 映射）；
  AXI 复制引擎要求 RAM 地址 8B 对齐，且**引擎写 RAM 不会失效 CVA6 的 D$**。
- 改 HAL：
  - upload ≤16 字走 MMIO 写 + `fence iorw`；>16 字走 `rt_dma_run`（WT，无需维护）。
  - download ≤128 字走 MMIO 读；>128 字走 DMA，**下载后 `rt_dcache_flush()`**。
  - 旧实现下载后没有 flush，真机上 CPU 会读到 D$ 里的旧值（仿真 HAL 没有缓存，
    所以之前 wlbench 混合运行能过）。
- 阈值宏 `CGRACC_MMIO_UP_WORDS` / `CGRACC_MMIO_DOWN_WORDS` 可在编译时覆盖。

## wlbench 物理层重构（16:40-17:20）

- 背景：用户指出 wlbench 里连 FFT 都没有，质疑"是否真在做无线通信运算"。
  结论确实如此（原版只有 MAC 调度面），按用户要求重构。
- 新增 `wlbench/include/wl_phy.h` + `src/wl_phy.c`（约 950 行）：
  CRC24A → K=7 卷积码(133/171) → 速率匹配 → Gold 加扰 → 38.211 QAM
  → 资源映射 → IFFT+CP → TDL 三径+AWGN → 去 CP+FFT → DMRS LS 估计
  → 3 抽头频域平滑 → MMSE 均衡 → max-log LLR → 解扰 → 解匹配
  → Viterbi → CRC。纯 C11、无 libm、固定数组，riscv64 交叉编译通过。
- 踩过的四个坑（都记一下，避免重犯）：
  1. 反变换没取共轭旋转因子 → IFFT 等于再做一次 FFT，子载波镜像。
  2. DMRS 是单位功率 QPSK（|X|²=1），LS 多乘了 2 → 信道估计整体大一倍。
  3. MMSE 去偏后噪声应为 σ²/|H|²，写成 σ²/μ² → LLR 尺度偏小、深衰落更糟。
  4. 频域 DFT 去噪：占用频段是 80..175 的带通段，IDFT 后冲激不在 0 附近，
     截断会把信号删掉；改成 3 抽头平滑（[1/4 1/2 1/4]）才成立。
- 数值验证（`make phy`）：FFT vs DFT 7e-15；四星座功率 1.0000；
  QPSK BER 0/4/8 dB 与理论 Q 函数误差 <1%；BLER 瀑布 −2dB 1.0 → 6dB 0；
  6 dB 上 post-FEC 8.7e-5 vs 未编码 2.3e-2。
- 接入：`wl_config.phy`，DL 调度的 ack 改由 `wl_phy_link` 的 CRC 决定，
  BLER 从"公式抽样"变成"实测"。schema 2，结果字 216 → 232（PHY 块追加在尾部，
  0..215 不变）。500 slot / 8 UE 全链路 1.35 s。
- 同步改动：`result_spec.py`、README、GPCP 的 `check_wlbench.py`(232)、
  `sim/soc/Makefile`(--nwords 150)、`sw/soc/Makefile`(加 wl_phy.o)、
  `link_wlbench.ld` 注释。裸机镜像 .bss 457 KB，_bss_end=0x80077768 < 0x80300000。
- 仍未做：LDPC/Turbo、MIMO 分层预编码、射频损伤、跨载波调度。
